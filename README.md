# 影视仓 / TVBox 配置（含直播源）

一份自包含的单仓配置：**25 个点播采集站 + 8 组直播（179 个频道位）**，全部写在
`config.json` 里，不依赖任何外部文件或解析器（不需要 spider jar）。

**本配置每天自动体检、重排、发布。** 下面的地址始终指向最新结果，不用手动更新。

## 配置地址

推荐（国内直连，实时）：

```
https://gh-proxy.com/https://raw.githubusercontent.com/foxfox123/tv-keep/config/config.json
```

备用：

```
https://ghfast.top/https://raw.githubusercontent.com/foxfox123/tv-keep/config/config.json
https://cdn.jsdelivr.net/gh/foxfox123/tv-keep@config/config.json
https://raw.githubusercontent.com/foxfox123/tv-keep/config/config.json
```

> jsdelivr 有 CDN 缓存，更新可能延迟几小时；前两个走 raw，提交后立刻生效。

## 怎么用

1. 打开影视仓 / 宝盒 / TVBox 系 App
2. 设置 → 配置地址（或「导入配置」）→ 粘贴上面的地址 → 确定
3. 首次加载需要几秒，之后每次启动都会重新拉取，自动拿到当天的最新源

## 自动更新做了什么

每天上午 10:10 跑一次 `tools/daily.py`：

1. 把配置里所有源展开去重（约 300 条），逐条以**播放器视角**检测——
   状态码、m3u8 合法性、**连续 3 个分片能否下到（容忍 1 个失效）**、按真实下载耗时算带宽、
   分片序号是否滚动。「能 ping 通」「单分片能下」都不算数；实测带宽跟不上视频码率、
   或分片到达忽快忽慢的源不淘汰，但排序时降权，让稳定源排到前面。
2. 剔除失效源，按 **纯IP+http > 纯IP > 域名+http > https** 重排主备顺序
   （盒子走域名容易卡在 DNS 解析上，这是实测结论）。
3. 同台名跨组借源：某个分组里这个台全挂了、但另一组同台名还活着，就直接复用。
4. 只在配置真的变化时才提交，commit 信息里带当天可用台数。

## 内容说明

- **点播**：25 个纯 HTTP 采集接口，无需解析器
- **直播**：8 组 179 个频道位
  - 央视频道（17）、卫视频道（16）、地方频道（2）
  - 央视·卫视(游魂源)（30）、央视精选(测速)（27）
  - 卫视精选(测速)（41）、港澳台精选(测速)（7）、地方台精选(测速)（39）
- 每台保留 4–6 条备源，播放器里可手动切线路

## 已知情况

- 约 162/179 个频道位当天有可用源。全挂的基本是长尾台（CETV2/4、三沙、兵团、
  香港卫视、八大精彩台等），公开源本就稀缺，不做保证。
- CCTV 全套、各省卫视是主要保障对象，母源失效时会自动切到备源。
- `/tsfile/` 类源能播但首帧要 30–45 秒（服务器推流慢），排序时已降权，
  非必要不排在首位。
- 公开源站寿命通常几周到几个月，所以这套东西的价值不在"跑出一次好结果"，
  而在**每天都能重跑一遍**。
