# tv-keep · 影视仓点播/直播自动保活

电视上只填**一个永远不变的地址**，地址背后的源每天自动换。

- **直播**：从多个公开直播源里只挑你要的台 → 逐条探活、剔掉死链和广告占位 → 每台留 6 条备用 → 输出一条 m3u。
- **点播**：把你现在用的多仓地址聚合 → 递归展开所有线路（线路里还套线路也能展开）→ 逐站探活 → 死站剔掉 → 输出一份你自己的多仓配置。线路还是原来那些，但里面只剩活着的站。

零第三方依赖，只用 Python 标准库。

## 一、为什么是这套架构

两个决定，都是被实测数据逼出来的。

### 1. 探测必须在你家电脑上跑

云端机器的出口基本都在境外（GitHub Actions 是，Cloudflare 也是）。而境外网络看国内直播源，结果和你在家完全不是一回事：大量运营商 CDN 的地址对境外 IP 返回 403，或者干脆不响应。**这不是源坏了，是测不到。**

我实测过：同样一份上游，境外 35 个台只有 22 个能出线路，而且排在最前的是 `74.91.26.218:82` 这种纯 IP 中转——在境外延迟 80ms，在国内往往拉不动。

如果每天在境外跑一次、把"测不到"当成"坏了"删掉，几天之后你的配置就被自己洗干净了。所以：

| 模式 | 怎么判断 | 用在哪 |
| --- | --- | --- |
| `geo_safe`（脚本默认） | 只剔**确定已死**的：域名解析失败、404、连接被拒。**403 和超时一律算"疑点"保留**，排在确认可用之后 | 万一在云端跑 |
| `strict`（`run-local.bat` 用这个） | 真拉分片、真测速率，按实测速度排序 | 家里这台电脑 |
| `off` | 完全不联网验证，只做合并去重 | 网络特别差时兜底 |

`geo_safe` 下没有可信速度，排序改用两个跟地理位置无关的信号：**这条线连续活了几天**，以及**它是域名还是纯 IP**（域名走正规 CDN，纯 IP 多是个人中转，活得短）。

第一次跑所有线路都只活了 1 天，看起来排序差不多；跑上一周差距就出来了。你在家跑 `strict` 时测到的速度会写进 `dist/live-hist.json`，下次排序就参考它——**跑得越勤，排得越准**。

### 2. 托管用 jsDelivr，不用 workers.dev

原本部署在 Cloudflare Workers，但 `*.workers.dev` 在国内被 DNS 污染了，实测：

| 域名 | 解析结果 | 判断 |
| --- | --- | --- |
| `tv-keep.651914570.workers.dev` | `199.96.59.61` / `108.160.167.148` | 不是 Cloudflare 的地址，**污染** |
| `www.cloudflare.com` | `104.16.123.96` | 真实 Cloudflare 网段 |

换成 jsDelivr 之后，仓库在 GitHub、内容由全球 CDN 分发，四个节点实测全部 200。

## 二、日常

绝大多数时候你什么都不用做。

**每天跑两次**（08:30 和 20:30），已经用计划任务配好了（任务名 `tv-keep`）：

- 想改时间：`taskschd.msc` → 找到 `tv-keep` → 属性 → 触发器
- 想立即跑一次：同一个地方点「运行」，或者直接双击 `run-local.bat`

`run-local.bat` 做三件事：直播真测速 → 点播探活 → 推送上线。

电脑那天没开就不更新，电视照旧播上一次的结果，**不影响使用**。

**想看效果**：打开本机 `dist/live-report.md`、`dist/vod-report.md`，关键三行：

- 直播：**今天哪几个台没找到可用线路** —— 这几个台的源该补了；
- 点播：**每条线路今天掉了多少站**；
- 点播：**本次剔除的站点** —— 谁挂了、为什么挂。

### 重要：更新到电视上会晚半天

这是 jsDelivr 的硬限制，我实测过绕过的方法，都不成立，所以说清楚免得你以后怀疑是不是坏了。

`publish.py` 推完会去线上核对版本，日志最后几行长这样：

```
本地版本：20261112191207-de30
线上版本：20261112191135-5747
jsDelivr 对已缓存的地址会锁最长 12 小时，加 ?t= 之类的参数也绕不过（实测）。
```

意思是：**配置本身是新的、没坏，只是 CDN 还没换过来。** 几个事实：

- jsDelivr 对每个文件的响应头是 `s-maxage=43200`，即边缘缓存 12 小时；
- 官方清缓存接口 `purge.jsdelivr.net` 对它**实测无效**：返回 `finished`，但四个节点照样给旧内容；
- 加查询参数（`?t=123`）、换 `@main` / 不带 `@main`、换 `fastly`/`gcore` 节点，都试过，都绕不过。

对使用的影响：**源挂了，最晚半天后才在电视上换掉。** 不是当天即时，但也不需要你手动做什么。

如果你确实要"发布后立刻生效"，只有两条路（都不是技术问题，是托管问题）：

1. 买一个域名（首年十几块）挂到已经部署好的 Cloudflare Worker 上，地址变成 `https://tv.你的域名/dist/multi.json`，改完立刻生效；
2. 用 Gitee 建同名仓库，raw 地址是动态的、不受这个缓存影响，但需要注册账号并做实名。

### 电视上没变，还有个可能

播放器自己的缓存。jsDelivr 头里还有 `max-age=604800`（7 天），个别播放器会照这个缓存。影视仓里「重置」或清一次应用缓存即可。

如果 `dist/` 里文件的时间超过一天没变，那是计划任务没跑成，通常是电脑没开机，或者 Python 环境被删了。看 `dist/run.log` 最后一段就知道。

## 三、按你的习惯调

### 直播：留下哪些台 → `live/channels.txt`

```
频道名 | 别名1,别名2 | 分组
CCTV-5 体育 | CCTV5,CCTV-5 | 央视频道
```

**不看的整行删掉。** 台越少，每台分到的探测预算越足。20 个台最舒服。

### 直播：加源 → `live/sources.txt`

一行一个 `备注 | 地址`。默认 5 个源按实测覆盖率排过（饭太硬 33/35、iptv-org 24/35、vbskycn 20/35、zhoujie 12/35）。

用的是 jsDelivr 镜像而不是 `raw.githubusercontent.com`——国内对 raw 的解析经常失败。镜像挂了脚本会自动换回 raw 重试。

`ipv6.m3u` 那行默认注释掉了：台更全、画质更好，但要求你的宽带和电视都支持 IPv6。能播再打开。

### 点播：把你正在用的地址粘进来 → `vod/sources.txt`

一行一个 `备注 | 地址`。**这一步最值得做**：你手机上收藏的那堆多仓地址，粘进来之后就成了后台输入，以后只管填自己这一个。

### 参数

`live/config.json`

| 参数 | 含义 |
| --- | --- |
| `probe_mode` | `geo_safe` / `strict` / `off`，见第一节 |
| `keep_per_channel` | 每个台保留几条备用线（默认 6，可调小到 3–4） |
| `min_kbps` | 仅 `strict` 生效：低于这个码率不采用（默认 300） |
| `workers` | 并发数，网络好可加到 32 |
| `epg` | 填了就在 m3u 里带节目单，如 `https://live.fanmingming.cn/e.xml` |

`vod/config.json`

| 参数 | 含义 |
| --- | --- |
| `probe_mode` | 同上 |
| `max_per_upstream` | 每条线路最多保留几个站（默认 45） |
| `max_repos` | 最多展开几条线路（默认 40） |
| `max_probe_sites` | 单次最多探多少个独立 API（默认 600） |
| `keep_sites` | 单仓最多保留多少站（默认 90） |
| `min_keep_sites` | 安全阀：存活站少于这个数就不覆盖旧结果 |

`cf/config.json` 里的 `public_base` 决定**所有地址的根**。改完必须重跑一次 `vod/build_vod.py` 才会生效，否则 `multi.json` 里每条线路还指向老地址，电视上每条线路都会 404。

## 四、三道保护（防止电视变黑屏）

1. **跌幅保护**：这次可用数量比上次少 40% 以上，直接放弃本次，保留旧结果。典型场景就是网络环境变了。
2. **空结果保护**：一条可用线路都没有时，绝不覆盖已有文件。
3. **疑点保留**：`geo_safe` 下 403/超时不会被当成死亡，所以"境外误杀"这条路被堵住了。

三道保护都只比较两次都存在的频道/站点，所以你删台、删源不会误触发。

真被拦下来时退出码是 2，日志里会写明原因。确认无误想强制覆盖，删掉 `dist/live-status.json` 或 `dist/vod-status.json` 再跑。

## 六、几句实话

1. **它不含任何影视内容**，只是配置整理和测速工具，源全由你自己填。看什么、是否合规，是你自己的责任。
2. **免费源一定会死**，这是结构性的。这个工具能做到「死了自动换」，做不到「永远不死」。
3. **jar 爬虫站（`csp_` 开头）无法在电脑上验证**，只能原样保留。这正是每条线路都必须保留上游自己 `spider` / `vars` 字段的原因——丢了它们，这类站全废。这是普通「合并去重」工具最容易踩的坑。
4. **`type:3` 的 js 源**（`api` 指向 `.js`）不是 JSON 接口，探测时看的是"脚本能不能下载下来"，不是"接口有没有返回列表"。混为一谈会把这些站全判死。
5. **上游塞了什么广告、什么跳转，本工具管不了**。挑口碑好的上游，别乱加来源不明的配置。
6. **电脑那天得开着**，这是"探测留在本地"的代价，换来的是测速真实。
